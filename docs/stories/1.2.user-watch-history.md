# Story 1.2: User Watch History Management

## Status
Draft

## Story
**As a** registered user,
**I want** to view my watch history and automatically track movies I've watched,
**so that** I can resume watching from where I left off and keep track of my viewing activity.

## Acceptance Criteria
1. System must automatically create watch history entries when receiving movie.watched events from Playback Service
2. User can retrieve their watch history via GET /api/v1/users/me/watch-history
3. Watch history must include movie ID, watch progress, duration, and timestamp
4. User can manually add watch history entries via POST /api/v1/users/me/watch-history
5. User can remove specific entries from watch history via DELETE /api/v1/users/me/watch-history/:id
6. Watch history entries must be paginated and sortable by watched date
7. System must handle authentication and authorization properly
8. System must return appropriate error responses for invalid requests
9. Watch history data must persist to the database with proper validation

interface MovieWatchedEvent {
  type: 'movie.watched';

**Event Flow** [Source: architecture/5-event-driven-architecture.md#52]
- Playback Service publishes movie.watched events to RabbitMQ
- User Service consumes these events to automatically create/update watch history
- Events should trigger user statistics cache updates
